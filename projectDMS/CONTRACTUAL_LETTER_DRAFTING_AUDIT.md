# Contractual Letter-Drafting System Audit

Date: 2026-07-27
Scope: customer-facing contractual letter drafting, LangGraph orchestration, state, tools, guardrails, validation, versions, review, editing, approval, export, and issue.

## Executive conclusion

The system has a mature source-aware drafting domain pipeline and an official LangGraph runtime with MongoDB checkpoints, Redis worker execution, optimistic state versions, immutable input/evidence snapshots, human interrupts, server-side engine selection, and an explicit v2 fallback.

This audit initially confirmed two P0 and five P1 governance defects. The implementation now:

- binds the legacy `Draft -> Review -> Approval -> Completed` workflow to the exact governed run artifact and approval chain;
- stops v2 before generation whenever required probing questions are unanswered;
- separates automated legal-risk scan time from human review evidence;
- replaces named LangGraph no-op stages with enforced checkpoint stage markers;
- makes draft acceptance idempotent and final lock/approval transactional on Mongo deployments with sessions;
- blocks critical input/evidence guardrail findings before generation and again at acceptance/approval;
- restores `drafting.final.approve` to the canonical permission catalog.

The frozen-section feature also closes the scoped AI-editing gap: frozen and unselected content is reconstructed server-side, never regenerated by the model, and rechecked before validation and approval.

The live create route is:

`POST /api/letters/{letter_id}/drafting/runs`

It hashes the request and selects the engine on the server:

- v2: synchronous `DraftRunService.create_run()`
- LangGraph v3: asynchronous `LangGraphDraftingEngine.create()` plus polling/resume

Code defaults are `DRAFT_ENGINE_DEFAULT=v2` and `DRAFT_ENGINE_ROLLOUT_MODE=off`. These are repository defaults, not a claim about current production environment values.

## End-to-end governed workflow

1. Authenticate, rate-limit, and authorize organization/project/letter scope.
2. Create an idempotent run from a canonical request hash.
3. Retrieve current input, selected documents, correspondence, clauses, graph-thread records, and governance comments.
4. Assign stable source IDs, permitted-use labels, scope metadata, and hashes.
5. Scan all untrusted input/evidence for injection or instruction manipulation.
6. Analyze incoming correspondence and verify cited clauses.
7. Generate deterministic probing questions.
8. Interrupt with `awaiting_user_direction` until every required versioned question is answered.
9. Build the planning sheet, reply matrix, integrity summary, and strategy.
10. Generate and cyclically validate the draft with bounded refinement.
11. Calculate assertion support/confidence and scan legal risks.
12. Permit scoped AI edits only as hashed child revisions; preserve frozen and unselected sections byte-for-byte.
13. Require drafter, reviewer, and final approval by ordered, separated actors.
14. Bind every legacy status transition to the same run body/hash.
15. Accept/lock one idempotent draft version and record the approved run pointer.
16. Export only an approved run to immutable DOCX/PDF artifacts.
17. Issue only after both export artifact IDs exist.

## LangGraph orchestration

The graph is:

`START -> collect_evidence -> review_correspondence -> user_direction_gate -> strategy_gate -> draft_generation -> validation_review -> legal_risk_review -> approval_gate -> prepare_execution -> END`

Behavior:

- `collect_evidence` and `review_correspondence` checkpoint safe completion markers.
- `user_direction_gate` and `strategy_gate` use durable `interrupt()`.
- after strategy confirmation, the worker runs generation, cyclic validation, legal-risk, and approval-readiness as separate idempotent stages;
- the v2 generation adapter stops after producing the initial artifact; validation/refinement and legal-risk scanning execute in their own stages;
- each named graph node requires its corresponding persisted marker and checkpoints it;
- `prepare_execution` maps the persisted domain result to the public run status/action.

Checkpoint state contains IDs, schema versions, status values, and booleans only. Raw source text, answers, and draft content remain in Mongo domain records/snapshots. Checkpoint inspection redacts other values to hashes.

Residual orchestration work:

- evidence collection, analysis, planning, and initial generation remain bundled inside the mature generation adapter;
- add conditional remediation edges and node-specific retry policies;
- add cooperative cancellation checks within generation/refinement;
- enforce the configured checkpoint byte limit;
- implement explicit state-schema migration handlers.

## Frozen-section editing

Users can freeze blank-line-delimited sections, select non-frozen sections, and request only:

- rewriting;
- grammar and spelling correction;
- clarity and structure improvement;
- tone and formality adjustment;
- expansion;
- polishing.

Enforcement:

- the client sends indices, not trusted frozen text;
- the server captures exact section text and SHA-256 hashes;
- stale expected hashes are rejected;
- frozen sections cannot be selected for editing;
- only selected section text is sent to the model;
- the server reconstructs the full draft from original frozen/unselected content;
- clause, date, amount, and reference anchor drift is blocked;
- validation and legal-risk review rerun on the reconstructed artifact;
- acceptance and every approval stage recheck frozen/preserved integrity.

APIs:

- `POST /api/letters/{letter_id}/drafting/runs/{run_id}/freeze-sections`
- `POST /api/letters/{letter_id}/drafting/runs/{run_id}/revise-sections`

## Finding resolution

| Priority | Finding | Resolution |
|---|---|---|
| P0 | Governed runs and legacy mutable approvals were not bound to one artifact. | Resolved. Submit/review/complete advance drafter/reviewer/final run approvals and require exact body/hash continuity. Out-of-band edits are rejected. |
| P0 | v2 asked probing questions but continued drafting. | Resolved. v2 persists `awaiting_user_direction`, creates no artifact, validates required/versioned answers, and resumes through a linked child run. |
| P1 | Automated risk scanning populated `reviewed_at`. | Resolved. Scans set `scanned_at`; only the human endpoint sets `human_reviewed_at`, reviewer, and comment. Historical `reviewed_at` cannot satisfy approval. |
| P1 | Four named LangGraph nodes were no-ops and the mature pipeline ran as one adapter operation. | Resolved. Generation stops at the initial artifact; cyclic validation and legal-risk review run as separate idempotent stages; each named node requires/checkpoints its persisted marker. |
| P1 | Acceptance and final locking were non-idempotent and split across writes. | Resolved. One run maps to one version; replay returns it; accept-and-lock is one letter write; final letter/run approval uses a Mongo transaction when sessions are available. |
| P1 | Critical injection findings were advisory. | Resolved. Non-pass critical verdicts create a blocking finding before generation and are rejected again during acceptance/approval. |
| P1 | `drafting.final.approve` had permission-catalog drift. | Resolved. It is in `DRAFTING_PERMISSIONS` and `Permissions`; catalog parity tests pass. |

## Remaining risks and required follow-up

| Priority | Risk | Required improvement |
|---|---|---|
| P1 | Human free-text edits are mutable until a governed transition checks them; a mismatch is rejected rather than automatically versioned. | Convert every manual save into a hashed child revision with author, diff, parent hash, validation, and reset approvals. |
| P1 | The legacy `lock-paragraphs` API remains advisory. | Migrate remaining clients to frozen sections and deprecate it. |
| P2 | Evidence snapshots retain hashes/metadata, not content-addressed immutable source payloads. | Store immutable source blob/version references with retention guarantees. |
| P2 | `completed_at` defaults on queued runs. | Make it nullable until a terminal transition and add generated/approved/exported/issued timestamps. |
| P2 | Cancellation is checked mainly at worker boundaries. | Check cancellation between retrieval, planning, generation, each refinement, validation, and persistence. |
| P2 | Output guardrails are narrower than input/evidence injection controls. | Run the common output guardrail service on each final reconstructed artifact before approval. |
